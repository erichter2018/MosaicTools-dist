Triage Reason

When Mosaic's mosaicAI triages a study, MosaicTools reads WHY (e.g. "Suspected PE") and shows it in the notification box — so the reason for the triage flag is visible before you start reading.

What it does

When Mosaic flags a study as TRIAGED by mosaicAI, the flag alone doesn't tell you why. MosaicTools reads the triage reason from Mosaic and shows it in the notification box as a red-orange banner — for example, "TRIAGED (mosaicAI): Suspected PE" — so you know what the AI was worried about before you open the images. It's the same idea as the older Aidoc alert, for Mosaic's own triage.

How to turn it on / set it up

Nothing to configure beyond the notification box itself: as long as Settings → Alerts → Notification Box → Enable Notification Box is on (and Mosaic scraping is running), the triage reason appears automatically on any triaged study.

Using it

There's nothing to trigger. When a triaged study opens, glance at the notification box: if mosaicAI triaged it, the red-orange banner names the suspected reason. Studies that weren't triaged show no triage banner.

Tips & gotchas

  • The reason lives only in the triage tag's tooltip in Mosaic, so MosaicTools reads it with a brief one-time hover per study — you may see a momentary tooltip flicker on the Mosaic panel the first time a triaged study opens. It's read once per study, not repeatedly.
  • The banner reflects what mosaicAI suspected, not a confirmed finding — treat it as a heads-up, the same way you would a worklist triage flag.
  • Like the other notification-box alerts, this shares the box with the clinical-history display and works in alerts-only mode.
