Get Prior

Grabs the relevant prior study's date, time, and description from InteleViewer and folds it into ONE comparison line at the top of your transcript — newest study first, however many priors you pull.

What it does

Instead of reading the prior's date off InteleViewer and dictating "Comparison: CT chest from …", Get Prior extracts the prior study's information from InteleViewer — date, time, and study description — formats it through your comparison template, and pastes the finished line into the Mosaic report. It parses the raw InteleViewer text (including the timezone-stamped time) into a clean date, so the pasted line always reads the same way regardless of how InteleViewer displayed it.

How to turn it on / set it up

  1. Map the Get Prior action to a mic button or hotkey under Settings → Keys & Buttons.
  2. Customize the output under Settings → Text Templates → Get Prior Comparison, using placeholders: {date}, {time}, {description}, and {noimages} (the text to use when there's no prior).

Using it

  1. Have the prior selected/visible in InteleViewer.
  2. Trigger Get Prior.
  3. The formatted COMPARISON text lands in your Mosaic report. Done — carry on dictating.

The same prior information also feeds the Comparison line pinned at the top of the drafted-findings popup, so drafted cases show what the draft was compared against.

One comparison line (6.0.1)

Every prior you pull goes into a single statement at the top of the transcript, always in the same shape:

COMPARISON: 8/26/2026 CT abdomen and pelvis, 8/14/2026 CT head.
  • Newest study first, comma separated.
  • Pull a second prior and it is added to that line, not pasted as another one.
  • A line that says "None available" is replaced outright.
  • Pull the same prior twice and nothing changes — you get "Already in the comparison line" instead.
  • A comparison the drafting AI wrote as a bare date is replaced by the real one, so the same study never appears twice.
  • The automatic Clario comparison insert feeds the same line, so a report can never grow two.
  • Since 6.0.1 the line looks identical whether or not a comparison was already there — the leading -- marker that used to distinguish a manual pull is gone.

Tips & gotchas

  • The extraction is text-based: if InteleViewer's prior text is oddly formatted or nothing prior-like is on screen, nothing pastes — check that the prior is actually the active/selected study in InteleViewer and try again.
  • Occasionally the copy takes several seconds — that's InteleViewer fetching the prior's report text from the PACS server on demand (a cold fetch to a slow site), not MosaicTools. Since 5.5.28 you'll see "Prior: waiting on InteleViewer (loading report)…" during a slow fetch, and MosaicTools waits patiently instead of giving up.
  • (6.0.1) If a drafted comparison line is replaced by a different merged one, the original is struck through in the drafted findings popup, so you can see what it said before.
  • Get Prior gives you the reference line; if you want to know what the prior actually said, use Summarize Prior — it opens the full prior report with an AI summary on top. The two actions complement each other and many people map both.
  • The {time} placeholder is there for sites/modalities where same-day priors matter (e.g. ICU chest films); most people's templates use just {date} and {description}. The time is only filled in for priors from the last couple of days — an older prior leaves it blank, which is why the same template can produce a line with a time on one study and without on the next.
  • Fixed in 5.9.8: the exam could be missing from the pasted line, leaving just COMPARISON: 2/1/2024. with the date right and no study named. It happened when InteleViewer returned the prior with no status word on the end of its row — a normal shape for some studies — and it affected every modality. If you have been seeing bare dates in your comparison lines, that was this.
