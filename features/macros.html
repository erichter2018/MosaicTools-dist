Macros

Auto-inserts your text snippets into the transcript when a study matching your criteria opens — with per-macro study-description rules, a drafted-only option, and optional auto-processing afterwards.

What it does

When a study opens whose description matches a macro's criteria, MosaicTools types that macro's text into the transcript automatically — standard comments, technique lines, or a full report skeleton, placed before you say a word.

How to turn it on / set it up

  1. Check Enable Macros in Settings → Text & Templates → Macros (requires Scrape Mosaic to be on).
  2. Click Edit... to open the Macro Editor. Each macro has:
    • Criteria — required terms, any-of terms, and exclude terms matched against the study description.
    • Drafted studies only — only fire when Mosaic marked the study as having an AI preliminary draft.
    • A voice option, plus per-macro enable/disable.
  3. Optional: Add blank lines before macro text inserts blank lines above the macro so you have dictation space.
  4. Optional: Auto-process all studies after macro insertion (Settings → Behavior) waits for all opening macros to land, then runs Process Report automatically.

Using it

Open a matching study and the text is just there. Multiple macros can fire on one study if several match.

Tips & gotchas

  • Drafted-study timing is deliberate: Mosaic silently reverts a macro pasted too early onto a drafted study, so MosaicTools waits (default 3000 ms) after the draft renders. The Drafted-macro paste delay and Drafted-state wait controls in Settings → Behavior tune this — read the in-app warnings before lowering them.
  • If you use drafted-only macros, non-drafted studies pay the full Drafted-state wait (default 5000 ms) at open while MosaicTools waits to see whether the drafted flag appears.
  • Macros can be referenced from pick-list nodes by ID; the editor preserves those references across edits.
  • MosaicTools' own macro insertions don't count as "unprocessed dictation" for the premature-sign warning.
  • New in 5.9.10: MosaicTools now records what happens to every automatic insertion — that it landed, that no macro matched the study, or that a study waited too long and which step held it up. Nothing about how macros behave has changed. It means that if macros ever stop going in on you, saying so is now enough for the cause to be found afterwards; previously only the failures were noted, and several ways insertion can quietly stop were not recorded at all.
  • Fixed in 5.9.11: macros could fail to insert for one kind of study while working normally for every other kind - on CT head, neither the general macros nor the exam-specific ones went in. MosaicTools waits for the report to load before inserting and recognised only one spelling of the history heading, so a template beginning "HISTORY:" or "INDICATION" was never seen as loaded and every macro for that study type was skipped silently.
  • New in 5.9.11: the macro editor warns when a macro has no criteria at all. Such a macro is inserted into EVERY study, including other body parts - easy to do by accident, since a new macro starts with the criteria empty and enabled.
  • New in 5.9.20: Collapse macros to a short name (Settings → Text & Templates, under Macros). A long LLM instruction block sitting in the transcript is hard to dictate around. Turn this on, give a macro a short name in the macro editor's Shows as (short name) box, and the transcript shows a small coloured tag like [PET protocol] instead of the whole block; at Process Report it expands to the full text so Mosaic reads it, then shrinks back. Macros with no short name are unaffected. Two enabled macros must not share a name — while they do, NEITHER expands, and the editor warns you.
