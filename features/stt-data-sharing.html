Dictation Data Sharing (Opt-in)

Strictly opt-in sharing of de-identified dictation data to improve recognition accuracy — all PHI is stripped on your own machine before anything leaves it.

What it does

Recognition problems are fixed by looking at real dictations — which engine misheard what, and how the merge decided. Share de-identified dictation to improve accuracy contributes anonymized dictation data for exactly that tuning. The critical part is where de-identification happens: on your computer, before anything is shared. Names, dates, MRNs, accession numbers, and hospital/facility names are removed locally; nothing identifiable ever leaves your machine. Sharing is one-way (push only) and off by default.

A second, narrower opt-in — Contribute ~30 min of de-identified dictation audio to improve engine recommendations — is only visible to testers who have arranged it with the developer. Audio can't be scrubbed the way text can, so each clip is checked on your machine first and any clip with a detected identifier is dropped and never uploaded; it stops automatically at about 30 minutes total.

How to turn it on / set it up

Settings → Speech-to-Text → Data Sharing. Both boxes default to off; check the first if you're willing to contribute. Nothing else to do.

Using it

Invisible in daily work. The practical benefit flows back to you: engine misfires seen in the shared data drive keyterm additions, merge fixes, and ensemble recommendations in subsequent releases.

Tips & gotchas

  • Independent of this, ensemble mode keeps a local de-identified diagnostics log (dictation_log.jsonl, next to the main log) that never leaves your machine unless you personally send it — right-click the bar → Show Log to find it.
  • You can switch either opt-in off at any time; it stops immediately.
  • What's shared is dictation/diagnostic data — never raw patient reports with identifiers.
