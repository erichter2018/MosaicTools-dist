Native Process / Sign Watcher

Runs MosaicTools' usual post-Process/Sign follow-up even when you Process or Sign natively in Mosaic instead of through a MosaicTools button or hotkey.

What it does

Normally MosaicTools' follow-up actions — auto-showing the report, scrolling to the impression, stopping custom STT on sign — only run when MosaicTools triggers the Process or Sign. If you press Mosaic's own PROCESS REPORT or SIGN FINAL button (or its native hotkey), MosaicTools didn't know. With this on, MosaicTools detects the native action and runs the same follow-up regardless of how you triggered it:

  • Native Process → can auto-show the report and scroll to the impression (honoring your Report Display settings).
  • Native Sign → stops custom STT if it's still recording, and closes the MTRec Associations checklist.

How to turn it on / set it up

Settings → Experimental → "Run post-action effects on native Process / Sign." Off by default. Requires CDP (the direct-DOM connection to Mosaic).

Using it

Process or sign however you like — the button, a mic key, or a MosaicTools action — and the same things happen afterward either way. It detects the Process button greying out, and the SIGN button changing as the study closes.

Tips & gotchas

  • MTRec recommendations already re-run on any report change, and RVU/signed counting already happens on study close — this fills the remaining UI-effect gap, and won't double-count anything.
  • The MTRec Associations checklist also closes on any study change independently of this toggle; this is what closes it instantly when you sign a study that stays on screen (no auto-advance).
  • Experimental — behavior may change.
