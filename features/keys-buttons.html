Keys & Buttons

Map any MosaicTools action to a PowerMic button, a SpeechMike button, or a global keyboard hotkey — every action, one dialog.

What it does

Every MosaicTools action — Get Prior, Critical Findings, Process Report, Sign Report, Show Pick Lists, MTRec Recommendations, Auto Measure, and the rest — can be triggered from your dictation mic's buttons or a global hotkey. The Key Mappings dialog shows one row per action with a hotkey box and a mic-button dropdown.

How to turn it on / set it up

  1. Settings → Keys & Buttons. Under Dictation Microphone, pick Auto, PowerMic, or SpeechMike (Auto connects to whatever is plugged in); the status line shows what's detected.
  2. Click Open Keys Configuration... In the dialog, choose the device to configure (PowerMic or SpeechMike — each keeps its own mapping set), then per action:
    • Click the hotkey box and press a key combination to capture it.
    • Or pick a mic button from the dropdown.

PowerMic buttons: Left Button, Right Button, Record Button, T Button, Skip Back, Skip Forward, Rewind, Fast Forward, Stop/Play, Checkmark, Scan Button. SpeechMike buttons: Record, Play/Pause, Fast Forward, Rewind, EoL, Ins/Ovr, -i-, Index Finger, F1–F4.

Using it

Press the button; the action runs. MosaicTools reads the mic's HID interface directly, so mappings work regardless of which window has focus, and focus is saved/restored around Mosaic interactions.

Tips & gotchas

  • The settings page also lists the Hardcoded Mic Buttons — a default set (e.g. PowerMic Skip Back → Process Report, Record Button → Start/Stop Dictation, Checkmark → Sign Report; SpeechMike Ins/Ovr, -i-, Record, EoL for the same four) so a fresh install works before you customize anything.

  • SpeechMike works in Event mode; use Philips SpeechControl if you want the front mouse-style buttons behaving as hotkeys.

  • Global hotkeys are disabled in headless mode — mic buttons still work there.

  • MosaicTools tags its own injected keystrokes so an Alt-key mapping can't re-trigger itself.

  • A keyboard shortcut must include Ctrl, Alt or Shift. MosaicTools listens for its shortcuts everywhere, not only in Mosaic, so a shortcut with no modifier fires while you are simply typing. A shortcut like a bare A would fire every time you typed that letter, in any application.

    (5.9.11 refused bare letters and numbers. Since 5.9.18 this covers every bare key — Space, Home, End, the arrows, Insert, Delete and the function keys included. A bare Space was the worst of them: it fires on every word you type anywhere. If you had one assigned, MosaicTools switches it off at startup and tells you which action it was.)

  • Shortcuts that belong to something else are refused (since 5.9.18). Taking Ctrl+V would not give MosaicTools a shortcut — it would take paste away from every program on the computer. The editor declines them and tells you what owns the one you pressed:

    • clipboard and undo — Ctrl+C Ctrl+V Ctrl+X Ctrl+Z Ctrl+Y
    • document — Ctrl+A Ctrl+S Ctrl+P Ctrl+F Ctrl+H Ctrl+N Ctrl+O Ctrl+W
    • report formatting — Ctrl+B Ctrl+I Ctrl+U
    • Windows — Alt+Tab Alt+F4 Alt+Space Ctrl+Esc Ctrl+Shift+Esc Ctrl+Tab
    • Mosaic's own — Alt+P Alt+F Alt+R Alt+C (Process, Sign, Record, Copy), which MosaicTools also sends

  • Two actions cannot share one shortcut (since 5.9.18). Before, the second one was accepted and then simply never worked, with nothing said. The editor now names the action already holding it, so you know where to go and clear it.

  • A shortcut you already had saved is reported at startup if it can no longer be used (since 5.9.19). All three rules above are enforced as you type a shortcut into the editor — but a shortcut saved before those rules existed, or brought in by Settings Sync from another workstation, is only switched off when MosaicTools starts. Until 5.9.19 it said so in a message that faded after eight seconds, and MosaicTools usually starts before you sit down, so the first anyone knew of it was pressing a key and getting nothing back. A window now lists every shortcut that was switched off, what took it (paste, Alt+Tab, Mosaic's Alt+P, or another MosaicTools action), and why — with Open Key Mappings to go straight there. It stays on screen until you deal with it, and comes back at every startup while the shortcut is still one of the refused ones, because that action does not work until you change it.

  • Fixed in 5.9.13: when studies are combined or associated in Clario — an ultrasound with a separate Doppler code, or CTA chest with abdomen and pelvis — the mic could fail to switch itself on for the new study, silently, so the first thing you said was lost. Stopping the previous dictation takes a moment, and a combined study opens two studies close enough together that MosaicTools mistook "still finishing the last one" for "already listening". It now waits, then starts.
