Definitions and data coverage
  • Users: anonymous installation IDs are the available proxy for radiologists. A person using several installations can count several times; copied settings can share an ID. This is not a verified count of unique people.
  • Active users: installations with study or feature activity during the selected period. Process Report, Sign Report and Discard Study are excluded from feature rankings but still establish that an installation was working.
  • Uses per active workday: total feature triggers divided by the sum of active days for its users in this period, including zero-use days. The median is calculated from each user's own uses-per-day rate, giving each user equal weight. The main mean weights by active days.
  • Workdays with use: adopter-days with one or more feature triggers divided by all adopter-days. “Returned on another day” in the details means a user triggered the feature on at least two distinct days in the period.
  • Recorded use: an action request, not verified completion. Automatic recommendation insertions and subsequent DDx insertions are not added to their action counts. Settings and automatic fix counters do not enter feature rankings.
  • Dates: UTC calendar days including the current partial day. Older clients date all counts to the app session's start date; recent windows and working-day estimates are therefore approximate. Updated clients provide daily buckets without event timestamps. Frequency is withheld if dated history is incomplete.
  • Defaults: the latest settings-day baseline for each active installation's own build, not an inference from how many left the setting enabled. * marks any represented default-on baseline; conflicting build defaults are marked as mixed.
  • Previous period: adoption change in percentage points versus the preceding equal-length period, using that period's own active cohort. It is not a matched-user retention metric.
  • Privacy and coverage: this report exports fleet aggregates only. New counters awaiting client updates are shown as unavailable. The source catalogue still audits settings, documented features, actions, and historical counters even when they are not displayed as usage features.
