Failover Backup Engines

Spare engines you've set up but don't run in your ensemble automatically swap in when a member fails mid-shift — dictation keeps its full strength, then hands back when the engine recovers.

What it does

Cloud engines have outages, and API keys run out of credit — usually mid-shift. Failover turns every engine you've configured but aren't running in your ensemble into a backup pool: when any ensemble member goes down (provider outage, exhausted credits, or an engine that stays connected but silently stops producing transcripts), a suitable spare swaps into its slot automatically. Your dictation continues at full ensemble strength instead of quietly running a voter short. When the failed engine recovers, your normal ensemble is restored.

How to turn it on / set it up

Nothing to enable — any spare configured engine is automatically part of the pool. Settings → Speech-to-Text shows your current pool read-only under the Failover backups divider at the bottom of the ensemble section. The Quick Setup Wizard has an optional Backup engines step that explains this and helps you add a spare for resilience.

Using it

You'll usually learn a failover happened from the health light: the toolbar dot becomes a split circle (left half = configured ensemble, right half = what's actually running), and the health drawer names the substitution — "replaced by …". Fix the underlying account when convenient; nothing is urgent while the backup is covering.

Tips & gotchas

  • Failovers hold steady deliberately — hysteresis prevents flip-flopping every time an engine's health briefly wavers.
  • A backup can only cover a role it's capable of (a batch-only engine can't stand in as the streaming driver).
  • The best cheap insurance is one extra key you never otherwise use — pay-per-use engines cost nothing while idle.
