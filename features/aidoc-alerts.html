Aidoc Alerts

Watches the Aidoc widget and raises an orange alert when Aidoc has a positive finding that's actually relevant to the study you have open — irrelevant flags are filtered out.

What it does

Scrapes the Aidoc shortcut widget in the background and shows an orange border alert on the notification box when Aidoc has detected a positive finding for the current study. Findings are checked for study-type relevance before alerting, so an Aidoc flag that can't apply to your open study doesn't nag you.

How to turn it on / set it up

  1. Check Aidoc AI detection in Settings → Alerts → Alert Triggers.
  2. Required Aidoc configuration: in the Aidoc widget, set Contextual summary display → No animation. The animated display defeats the scrape; the settings page has a ? button showing exactly where this option lives.

Aidoc itself must be installed and running on the workstation — MosaicTools only reads its widget, it doesn't talk to Aidoc's servers.

Using it

Nothing to do during a shift: when you open a study that Aidoc has flagged positive (the red-dot indicator on a finding icon), the orange alert appears so you know to look for it before you start dictating. Negative/absent findings produce no alert.

Tips & gotchas

  • The relevance filter is the point: Aidoc's widget shows results for the patient, which may include findings from a different exam. MosaicTools verifies the finding type plausibly belongs to your open study's type before alerting.
  • Positive/negative status is read from the widget's colored indicator dots, so unusual display scaling or a themed/updated Aidoc widget can break detection — if alerts stop, check the widget still looks normal and animation is still off.
  • The Aidoc scrape runs independently of the clinical-history display, so it keeps working even with the notification box in alerts-only mode.
