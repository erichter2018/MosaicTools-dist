Copy MTRec Debug

One keypress copies a de-identified dump of the current case — the findings exactly as MTRec saw them plus the engine's full reasoning trace — to the clipboard, ready to paste into a bug report.

What it does

When MTRec recommends something you disagree with — or stays silent on a finding you expected it to catch — this action captures everything needed to reproduce the case. It reads the current report, runs the engine's diagnostic trace, and copies a structured dump to the clipboard: app version, engine mode, patient age, exam and history lines, which modules are enabled, the FINDINGS text exactly as the engine saw it (including the LLM-normalized version if you use AI-assisted extraction), the IMPRESSION, and the module-by-module analysis explaining what fired, what was suppressed, and why.

How to turn it on / set it up

Assign Copy MTRec Debug to a key or button under Settings → Keys & Buttons. MTRec itself must be enabled (Settings → MTRec) — otherwise the action just shows a "MTRec is not enabled" toast.

Using it

Press the key while the case is still open. A toast confirms the copy — "MTRec debug copied (de-identified, N redactions)" — and you can paste the dump straight into an email or message to the developer.

Tips & gotchas

  • The entire dump passes through the on-device de-identifier before it touches the clipboard: patient and physician names, dates, and MRNs are scrubbed. The engine ran on the real text first, so the reasoning trace is accurate; only the copied text is redacted, and the toast tells you how many redactions were made.
  • Fire it in the moment. The dump reflects the report currently on screen — once you've moved to the next case, the reproduction is gone.
  • This is the single most useful thing you can send when reporting an MTRec quirk: it turns "it missed my nodule yesterday" into a case the developer can replay offline against the engine's test harness.
