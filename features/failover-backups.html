Automatic Failover

When a dictation engine has a sustained outage, MosaicTools re-picks the best ensemble from the engines you have keys for — automatically, between dictations, with nothing to configure.

What it does

Cloud engines have outages, and API keys run out of credit — usually mid-shift. MosaicTools watches every engine in your ensemble and, when one is genuinely down, rebuilds the lineup around it so your dictation keeps its strength instead of quietly running a voter short.

Three things count as an outage: a hard failure (authentication, billing, or policy), a sustained error rate, and — the one that used to go unnoticed — an engine that stays connected but stops producing transcripts. That last case raises no error at all, so it's caught by noticing that other engines heard speech this one missed.

MosaicTools then re-runs its accuracy table over the engines that are still healthy and that you hold a key for, and switches to the best ensemble it can actually build. That can mean promoting a different engine to the streaming driver role and refilling the voters around it — it isn't a like-for-like slot swap.

How to turn it on / set it up

Nothing. As of v5.8.29 there are no failover settings and no per-slot backup pickers.

Every engine you hold a key for is automatically in the pool. Assigning a backup by hand could only ever name a subset of what failover already considers, so those pickers were removed, along with the tuning thresholds — which are now fixed internally rather than exposed.

The one useful thing you can do is hold a key you don't otherwise use. Pay-per-use engines cost nothing while idle, so a spare key is cheap insurance that widens the pool.

Using it

Switches happen between dictations, never in the middle of one — an engine that dies mid-recording is ridden out for that recording.

You'll usually learn a failover happened from the health light: the toolbar dot becomes a split circle (left half = configured ensemble, right half = what's actually running), and the health drawer names the substitution — "replaced by …". Fix the underlying account when convenient; nothing is urgent while the backup is covering.

Tips & gotchas

  • A widespread outage does not trigger a failover. If several engines go red at once it's your network, not the providers — every cloud backup would be equally affected — so MosaicTools holds its lineup and lets the connections recover.
  • A switch is held for a few minutes before another is allowed, so a wavering engine can't make the ensemble thrash. The exception: if the streaming driver itself is failing, it switches immediately rather than riding a dead one.
  • An engine in a sustained outage is retried periodically, so topping up a depleted account brings it back on its own.
  • A backup can only cover a role it's capable of (a batch-only engine can't stand in as the streaming driver).
  • Separately: if most of your engines go dead at once and you're not dictating, MosaicTools rebuilds all speech connections in place — the same recovery as quitting and reopening, without losing your study. That's always on. Restarting the application if that still doesn't help stays an explicit opt-in under Settings → Speech-to-Text → Recovery.
